## 결론

AI 제품의 경쟁 우위는 보유한 데이터의 양보다 고객의 중요한 일을 수행하고, 결과를 확인하고, 다음 실행을 개선하는 전체 학습 구조에서 나온다.

> 업무를 수행한다 → 상황과 행동을 기록한다 → 결과를 평가한다 → 모델·규칙·운영을 고친다 → 다음 고객 결과를 개선한다

데이터는 이 구조의 재료다. 업무 소유권, 공통된 의미, 평가 기준, 사람의 판단, 결과에 영향을 줄 권한이 없으면 데이터가 늘어도 경쟁 우위가 자동으로 생기지 않는다.

## 경쟁 우위를 만드는 다섯 층

| 층 | 필요한 기록 | 개선에 쓰는 방법 | 주요 한계 |
| --- | --- | --- | --- |
| 업무 맥락 | 고객 상황, 도메인 지식, 시스템 상태 | 현재 조건에 맞는 판단과 실행을 만든다 | 고객마다 다르면 공통 자산으로 만들기 어렵다 |
| 실행 과정 | 초기 상태, 작업 환경, 도구 사용, 중간 결정 | 실패가 모델, 데이터, 도구, 정책 중 어디서 생겼는지 나눈다 | 문서만 모으면 실제 작업 방식을 알 수 없다 |
| 사람의 반응 | 수락, 거절, 수정 내용과 이유 | 전문가의 판단을 다음 실행 규칙과 평가 예시로 바꾼다 | 횟수가 많아도 수정 이유와 결과가 없으면 뜻이 약하다 |
| 결과와 평가 | 업무 결과, 사업 지표, 테스트, 채점 기준, 금지 조건 | 좋은 실행을 판별하고 개선 전후를 비교한다 | 결과가 늦거나 외부 요인이 크면 원인을 밝히기 어렵다 |
| 공통 의미 | 용어 정의, 지표 관계, 출처, 권한, 최신 여부 | 서로 다른 시스템의 정보를 같은 뜻으로 연결한다 | 잘못된 정의를 쓰면 오류를 더 빠르게 확산시킨다 |

## 제품 학습 루프

1. 반복되며 결과 가치가 큰 업무 하나와 성공 기준을 고른다.
2. 초기 조건, 실행 과정, 사람의 수정, 최종 결과를 하나의 기록으로 연결한다.
3. 테스트, 전문가 채점표, 정책, 사업 지표로 결과를 평가한다.
4. 실패 원인을 모델, 지시, 도구, 데이터, 정책, 승인 과정으로 나눈다.
5. 좋아진 평가가 실제 고객 결과에도 이어지는지 확인한 뒤 다음 실행을 바꾼다.

같은 기반 모델을 쓰는 경쟁사도 고객 관계, 시스템 연결, 예외 처리, 평가 기준, 신뢰 기록까지 한꺼번에 복제하기는 어렵다. 경쟁 우위는 이 반복 구조가 실제 결과를 더 빠르고 안정적으로 개선할 때 커진다.

## 도입 난이도와 학습 속도

| 문제와 도입 조건 | 학습 기회 | 방어력 | 주의점 |
| --- | --- | --- | --- |
| 쉬운 문제, 쉬운 도입 | 사용과 반응이 빠르게 쌓인다 | 낮다 | 기반 모델 회사와 다른 제품이 기능을 쉽게 복제한다 |
| 어려운 문제, 쉬운 도입 | 반응은 많지만 정답 판별이 어려울 수 있다 | 중간 | 자본이 큰 경쟁자가 들어오고 사용자가 쉽게 이동할 수 있다 |
| 쉬운 문제, 어려운 도입 | 연결 과정에서 고객별 업무 지식이 쌓인다 | 교체 비용은 높을 수 있다 | 고객별 설정이 전체 모델의 개선으로 이어지지 않을 수 있다 |
| 어려운 문제, 어려운 도입 | 희소하지만 깊은 업무 지식을 얻는다 | 높을 가능성이 있다 | 사례가 적고 맞는 결과를 확인하기 어려워 학습이 느리다 |

도입 마찰을 줄이면 피드백 속도는 높아진다. 그러나 쉬운 도입 자체가 방어력은 아니다. 반응의 빈도와 결과 판별 가능성을 함께 봐야 한다.

## 제품 설계 원칙

### 기능보다 결과를 먼저 정한다

- 누가 어떤 결정을 더 잘 내려야 하는지 정한다.
- 만든 문서나 화면 수 대신 끝낸 일, 줄인 오류, 아낀 시간, 높아진 수익처럼 고객 결과를 측정한다.
- 도구로 남을지 서비스 결과까지 책임질지 정하고 운영 범위를 그 선택에 맞춘다.

### 평가를 제품과 함께 만든다

- 전문가 지식을 문서만으로 받지 말고 실제 과제, 환경, 좋은 결과 예시, 채점표, 금지 조건으로 나눈다.
- 실험 점수와 실제 고객 결과를 따로 측정하고 둘의 연결을 확인한다.
- 추천이 실제 행동으로 이어졌는지 추적해 다음 개선 과제로 사용한다.

### 의미와 권한을 관리한다

- 정보를 한곳에 복사하는 것보다 용어, 지표, 관계, 출처를 일관되게 관리한다.
- 구조화 데이터에는 스키마를 쓰고 기업 문서에는 분류 체계와 개념 관계를 함께 관리한다.
- 고객별 데이터와 여러 고객에게 공통으로 쓸 평가·오류 분류·운영 도구를 분리한다.

## 실패 조건

- 데이터를 학습과 제품 개선에 사용할 권리가 없으면 축적량이 커도 재사용할 수 없다.
- 결과가 늦게 나타나거나 외부 요인이 크면 어떤 실행이 성과를 만들었는지 확인하기 어렵다.
- 고객마다 업무가 크게 다르면 깊은 통합이 반복 자문 비용으로 남고 공통 제품 자산이 되지 못한다.
- 기반 모델의 개선이 기존 데이터와 평가의 차별성을 빠르게 줄일 수 있다.
- 정확한 데이터라도 해석, 추천, 관계적 신뢰, 실행 권한이 없으면 조직의 결정을 바꾸지 못한다.
- 업무 전체를 맡으면 방어력과 함께 운영비, 규제, 품질 책임, 자본 부담도 커진다.
- 투자자와 공급자가 제시한 시장 규모와 포트폴리오 성과는 중립적인 비교 근거로 다시 확인해야 한다.

## 전략적 판단

- hypothesis: 강한 AI 제품은 고유한 데이터 파일보다 검증된 학습 주기를 경쟁사보다 빠르게 반복한다.
- hypothesis: 경쟁 우위를 보려면 저장한 기록 수보다 확인 가능한 업무 완료 수, 수정 반영 시간, 같은 오류의 재발률, 고객 결과의 개선 폭을 측정해야 한다.
- hypothesis: 고객별 설정과 기록은 교체 비용을 높일 수 있지만 여러 고객에게 공통으로 적용되는 모델 개선과는 별개로 평가해야 한다.
- hypothesis: 정보의 공통 의미를 관리하는 일은 데이터 정리뿐 아니라 모델 행동을 간접적으로 통제하는 제품 기능이다.
- hypothesis: 데이터 팀의 역할은 정보 전달을 넘어 공통 정의, 현재 맥락의 해석, 실행 결과에서 배우는 구조를 관리하는 데까지 확장될 수 있다.
- hypothesis: 결과를 평가하고 다음 실행을 바꾸지 못하는 시스템은 기록이나 행동을 자동화해도 장기 경쟁 우위를 만들기 어렵다.
