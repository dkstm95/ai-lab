## Ingest Focus

이 노트는 Garry Tan이 제시한 퍼스널 AGI의 정의, 개인 지식 시스템의 구조,
스킬 파일 작성법, 반복 작업의 자산화 방식, 기억 관리의 위험, 인지 자산의 소유권
주장을 정리한다. 영상 설명과 영어 자막을 공식 Y Combinator 원문과 대조했으며,
전체 자막은 복제하지 않는다.

## Structured Notes

### 퍼스널 AGI는 제품이 아니라 축적되는 개인 자산이다

- Tan은 AGI가 어느 날 단일 사건으로 등장하기보다, 개인의 맥락에서 일을 수행하는
  에이전트와 기반 시설의 형태로 이미 퍼지고 있다고 주장한다.
- 그가 말하는 퍼스널 AGI는 사용자가 통제하는 기반 시설에서 실행되고, 사용자가 소유한
  기억을 읽으며, 사용자가 작성한 절차를 실행하는 에이전트다.
- 구독형 챗봇은 회사가 제품을 바꿀 때 함께 바뀌지만, 개인 시스템은 사용할수록 자신의
  기록과 절차가 쌓인다는 점에서 다르다고 본다.
- 그는 시스템을 `임대한 최신 모델 + 소유한 개인 맥락 + 둘을 연결하는 하네스`로
  설명한다. 모델은 점차 범용 상품이 되지만, 개인 맥락은 다른 사람이 가질 수 없는
  차별점이라는 주장이다.
- Tan은 자신의 2013년 대비 코드 산출량이 약 400배 늘었다고 계산했다. 코드 부풀림과
  자기 평가의 편향을 크게 감안해도 최소 8배, 중간 추정으로는 그보다 훨씬 크다고 말한다.
  이는 통제된 생산성 연구가 아니라 발표자의 경험 보고다.
- 그는 같은 모델과 API를 써도 큰 성과 차이가 나는 이유를 모델 가중치보다 적절한 맥락,
  맥락의 관련성, 작업 흐름에서 맥락을 제공하는 시점에서 찾는다.

### 개인의 삶은 도서관이고 에이전트에는 사서가 필요하다

- Tan은 제한된 인간의 작업 기억과 긴 LLM 컨텍스트를 대비한다. 긴 컨텍스트가 있어도
  개인의 전체 기록을 한 번에 담을 수 없으므로, 현재 작업에 맞는 자료를 고르는 방식이
  시스템 품질을 좌우한다고 본다.
- 그는 개인 지식 시스템을 도서관과 사서의 결합으로 설명한다. 도서관은 이메일, 회의,
  결정, 사람, 프로젝트, 실수 같은 기록이고, 사서는 현재 작업에 필요한 자료를 고른다.
- Tan은 자신의 GBrain에 약 22만 개의 Markdown 페이지와 25년 동안의 기록이 있으며,
  에이전트가 이를 수집, 정리, 검색한다고 보고한다.
- 그는 이 시스템이 이메일을 단순 분류하지 않고 과거 관계와 관련 사례를 붙여 브리핑으로
  만들며, 회의 준비 문서와 야간 조사 결과를 미리 작성한다고 설명한다.
- 시스템은 처음부터 거대한 창고로 만들지 않았다. 몇 개의 회사와 사람을 기록한 작은
  Markdown 폴더에서 시작해 에이전트가 매일 정리하면서 커졌다고 말한다.

### 스킬 파일은 자연어로 쓴 실행 절차다

- Tan이 제시한 구조는 두꺼운 스킬과 얇은 하네스다. 핵심 절차는 사람이 읽을 수 있는
  Markdown에 두고, 에이전트에는 브라우저처럼 세상에 작용할 수단을 준다.
- 실제 예시에서는 회의 녹음이 들어오면 화자를 구분해 전사하고, 약속, 담당자, 기한을
  추출하며, 등장인물을 지식 페이지와 연결하고, 기존 판단과 충돌하면 덮어쓰지 말고
  표시하도록 지시한다.
- 그는 똑똑한 신입이 그대로 수행할 수 있을 만큼 명확한 자연어 지시라면 에이전트도
  실행할 수 있다는 기준을 제시한다.
- 이 관점에서 Markdown은 코드처럼 작동하고 언어 모델은 컴파일러 역할을 한다. YC의
  비개발 직군도 스킬 파일과 예약 작업을 만든다는 사례를 제시한다.

### 판단과 정확 계산을 같은 방식으로 처리하지 않는다

- Tan은 취향, 판단, 모호한 요구 해석을 잠재 공간의 계산으로 분류한다. 이런 작업은
  언어 모델이 수행하고 Markdown 지시로 방향을 잡는다.
- 산술, SQL 질의, 대규모 일정 배치처럼 정확성과 일관성이 필요한 계산은 결정론적 코드와
  데이터베이스에 맡겨야 한다고 말한다.
- 다섯 명의 좌석을 정하는 일은 모델의 판단으로 처리할 수 있지만, 수천 명의 개인 일정을
  만드는 일은 모델이 코드와 데이터 구조를 사용해야 한다는 예를 든다.
- 그는 에이전트 실패의 큰 원인을 두 계산 영역을 혼동하는 데서 찾는다. 실용적인 시스템은
  Markdown 지시가 데이터베이스와 스크립트를 호출하는 혼합 구조를 쓴다.

### 한 사람과 에이전트가 작은 조직처럼 일한다

- Tan은 스킬 파일을 한 가지 일을 맡은 직원, 요청을 적절한 스킬에 보내는 resolver를
  조직도에 비유한다.
- 이 구조를 쓰면 한 사람이 회사를 세우기 전에도 에이전트와 함께 작은 조직처럼 일할 수
  있고, 예전에는 한 사람의 1년치였던 작업을 더 짧은 기간에 처리할 수 있다고 주장한다.
- 제작 비용이 낮아지면 한 사람만을 위한 도구도 만들 수 있다. 개인 문제를 해결한 도구를
  다른 사람도 요청하기 시작하면 제품이나 회사의 출발점이 될 수 있다는 논리다.

### 오늘 시작하는 다섯 단계

1. 하네스를 하나 골라 자기 컴퓨터에서 에이전트를 실행한다. Tan은 OpenClaw와 Hermes
   Agent를 쓰지만, Claude Code나 Codex 등 다른 도구도 핵심 개념을 구현할 수 있다고 말한다.
2. 거대한 아카이브 대신 Markdown 폴더 하나로 도서관을 시작한다. 노트와 이메일을
   내보내고, 현재 프로젝트와 함께 일하는 사람마다 한 페이지를 만든다.
3. 매주 반복하며 가장 싫어하는 일 하나를 골라 첫 스킬 파일로 만든다. 신입 동료에게
   설명하듯 적고, 결과가 틀릴 때마다 규칙과 예외를 보완한다.
4. 그 스킬을 매일 아침이나 매주 금요일처럼 반복 실행하도록 연결한다. 자는 동안 끝난
   결과를 받는 경험이 작업의 시간 단위를 바꾼다고 설명한다.
5. 일회성으로 끝내지 않는다. 작업이 끝날 때 수행 방식을 재사용 가능한 Markdown 스킬로
   추출해 다음 작업의 자산으로 남긴다.

- Tan은 첫 주에는 도서관과 스킬이 빈약해 수정 비용이 더 클 수 있다고 경고한다. 약 4주가
  지나면 개인 맥락을 활용하기 시작하고, 약 12주에는 여러 반복 작업과 빌려달라는 요청을
  받는 개인 도구가 생길 수 있다고 예상한다. 이 일정은 보장된 결과가 아니라 발표자의
  경험적 전망이다.

### 기억은 양보다 위생이 중요하다

- Tan은 관리하지 않은 지식 저장소를 검색만 잘되는 쓰레기장에 비유한다. 오래된 사실을
  확신 있게 꺼내거나 나쁜 절차를 반복할 수 있기 때문이다.
- 그는 사실마다 출처를 남기고, 새 정보가 기존 판단과 충돌할 때 감지하며, 불필요하거나
  낡은 내용을 정리하는 사서 역할이 필요하다고 말한다.
- 검색 자체는 기본 기능일 뿐이다. 무엇을 기록하고, 어떻게 연결하고, 자주 쓰는 기억과
  보관용 자료를 어떻게 나누며, 충돌을 누가 판단하는지가 실제 제품이라고 주장한다.

### 스킬 소유권은 인지 자산의 통제 문제다

- Tan은 스킬 파일을 머릿속 판단을 추출해 실행 가능하게 만든 인지 자산으로 본다.
- 가상의 지원 엔지니어 사례에서 스킬이 개인 저장소에 있으면 이직 뒤에도 축적된 판단을
  가져갈 수 있지만, 회사 저장소에만 있으면 회사가 그 판단을 계속 실행하고 개인은 가져갈
  수 없다고 대비한다.
- 그의 규범적 결론은 개인이 자신의 스킬을 소유해야 한다는 것이다. 퍼스널 AGI를 에이전트
  시대에 자신의 능력을 스스로 통제하는 방식으로 설명한다.
- 이 주장은 실제 고용 계약, 업무상 저작물, 영업 비밀, 보안 정책이 정하는 권리 관계를
  대신하지 않는다.

### 반론과 위험

- 더 좋은 모델이 하네스를 무의미하게 만든다는 반론에 대해, Tan은 모델이 좋아질수록 같은
  모델을 쓰는 사람 사이의 차이가 개인 맥락으로 이동한다고 답한다.
- 이것이 단순한 RAG라는 반론은 일부 인정한다. 다만 검색은 원시 기능이며, 검색할 가치가
  있는 지식과 관리 절차를 만드는 일이 더 어렵다고 본다.
- 이메일, 회의, 가족 일정까지 한 시스템에 모으면 유출 피해가 커진다는 반론도 제기한다.
  Tan은 자신의 기반 시설, 저장소, 키로 직접 보관하는 것이 대안이라고 답하며 이를
  custody로 표현한다.
- 직접 보관은 제3자 의존을 줄이지만 자동으로 안전을 보장하지 않는다. 키 관리, 접근 통제,
  백업, 암호화, 최소 수집, 삭제 정책 같은 운영 통제가 별도로 필요하다.

### 공개와 개인 문제 해결

- Tan은 하네스, 지식 구조, 스킬을 공개한 이유를 강한 도구가 소수에게만 머무르지 않게
  하려는 선택으로 설명한다.
- 그는 희귀 뇌전증이 있는 아들을 위해 한 아버지가 진료 기록, 논문, 발작 기록, 약물
  상호작용을 약 8만 개의 Markdown 파일로 정리했다는 사례를 든다.
- 이 사례에서 퍼스널 AGI는 범용 벤치마크가 아니라 한 사람의 중요한 문제에 관련 기록을
  제때 연결하는 시스템이다. 의료적 정확성이나 효과를 검증한 사례 연구는 아니다.

## Practical Interpretation

- 개인 AI의 지속 자산은 특정 모델보다 이동 가능한 원문, 정리된 지식, 스킬 파일, 실행
  기록이다. 모델이나 하네스를 바꿀 수 있도록 공개 형식과 버전 관리를 우선한다.
- 스킬 파일은 반복 작업을 줄이는 동시에 개인이나 조직의 판단을 고정한다. 출처, 변경 이력,
  검토자, 충돌 처리, 폐기 조건을 함께 설계해야 한다.
- 모호한 판단은 모델에 맡기되, 대규모 계산과 중요한 제약은 결정론적 코드와 검증기로
  감싸는 구조가 안정적이다.
- 개인 기록을 모을 때는 소유권만 강조하지 말고, 민감도 분류, 최소 수집, 암호화, 권한,
  백업, 삭제, 사고 대응까지 하나의 운영 모델로 다뤄야 한다.
- 업무 중 만든 스킬의 귀속은 철학적 주장으로 결정되지 않는다. 개인용과 회사용 저장소의
  경계, 계약, 법률, 보안 정책을 먼저 확인해야 한다.

## Source Limits

이 노트는 제공된 한국어 자막 영상의 설명과 영어 자막을 Y Combinator가 공개한 공식 영어
원문과 대조해 요약한다. 생산성 배수, Markdown 페이지 수, 제품 사용, 회사 성장, 공개
프로젝트 규모, 개인 사례는 발표자의 보고이며 독립적으로 재현하거나 검증하지 않았다.
역사, 인지과학, 보안, 의료 관련 설명도 이 영상 외의 1차 자료로 확인하지 않았다. 영상은
개인 지식과 스킬의 소유를 강하게 주장하지만, 실제 권리는 계약, 지식재산권, 개인정보,
보안 정책과 관할 법률에 따라 달라진다. 제품 이름, 기능, 수치와 링크는 2026년 8월 이후
바뀔 수 있다.
